# Компіляція через cml прямо в my-idea

my-idea вміє компілювати `.lisp`-файл через справжній компілятор **cml**
(`juv4uk/cml`) у нативний x86-64 freestanding ELF і одразу запускати
результат — кнопка **"🔧 Компілювати (cml)"** поруч із "⚡ Обчислити" й
"▶ Запустити".

Це не нова експериментальна робота: `CompilerBridge`/`CompilerBuildAdapter`
(issue #16) уже існували в коді, повністю покриті контрактними тестами —
але, як і з плагінами (#41), жоден Tauri-command чи кнопка в UI до них не
доходили. Ця зміна вперше робить компіляцію реально доступною з
інтерфейсу.

## Три різні дії — не плутати

- **⚡ Обчислити** — виконує код прямо в процесі (наш tree-walking
  інтерпретатор my-lisp, in-process).
- **▶ Запустити** — запускає файл через реальний CLI-бінарник `my-lisp`
  як окремий процес (той самий інтерпретатор, але зовнішнім процесом).
- **🔧 Компілювати (cml)** — компілює через **cml**, наш окремий,
  авторитетний компілятор my-lisp у нативний код, і запускає скомпільований
  артефакт.

my-idea ніколи не переносить семантику cml в себе — лише запускає `cml`
як зовнішній процес і показує його діагностику дослівно.

## Чесна межа (важливо!)

cml на цьому етапі — **freestanding x86-64 backend, лише чисті обчислення**.
`(+ 40 2)` компілюється й запускається без проблем. Побічні ефекти на
кшталт `print` **ще не підтримуються** цим бекендом (немає libc/stdio у
freestanding-режимі) — спроба скомпілювати щось із `print` дасть помилку
компілятора: `unsupported IR in x86_64-freestanding backend: Var (unbound)`.

Тобто "компілювати в IDE" зараз реально працює й перевірено на справжньому
ELF-бінарнику (`src-tauri/tests/real_cml_compiler_contract.rs`), але поки
що корисне для дуже вузького класу програм. Розширення можливостей cml —
це робота в самому `cml`, не в my-idea.

## Як резолвиться бінарник cml

Той самий патерн, що й для `my-lisp`-сайдкара:
1. `MY_IDEA_CML_BIN` — явний шлях (env);
2. сусідній чекаут `../cml/target/release/cml` відносно відкритої
   робочої теки;
3. `cml` з `PATH`.

## Технічний потік

```text
"🔧 Компілювати" → compile_lisp_source (Rust)
                       → CompilerBuildAdapter::compile_project (cml)
                       → діагностика в REPL-консоль
                       → успіх? → start_build (та сама панель Build Output,
                                  що й для "▶ Запустити")
```

Компілятор лише компілює й повертає готовий `BuildSpec` — саме запускання
й показ виводу переюзує вже наявну інфраструктуру Build Output панелі,
без нової окремої панелі.
